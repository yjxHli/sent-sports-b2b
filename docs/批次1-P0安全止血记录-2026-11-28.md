### P0-05 库存超卖

| 文件 | 改动 |
| --- | --- |
| `stock/mapper/StockMapper.java` | `updateLedger(...)` 增加 `AND version = #{version}` |
| `stock/repository/StockRepositoryImpl.java` | `save()` 改用 `selectBySkuIdForUpdate` 行锁读；**只覆盖实物量**，锁定/在途/冻结沿用锁内读数；0 行更新 → 40901 |
| `seed/DemoDataGenerator.java` | 两处 `updateLedger` 调用补 `version`（演示数据，行为不变） |

> 只加行锁还不够：`@UseCase` 事务内 `findBySku` 是快照读，调用方手里的 `StockItem` 可能已过期，
> 若仍把它的 `lockedQty` 覆盖回去，丢更新照旧。因此「只改实物量 + 锁内读数回写 + 版本兜底」三者缺一不可。
> `RepositoryIT` 里原先断言「save 会把 locked 清 0」，正是该漏洞的副作用，已改为断言「不得清空并发预占」。

## 6. E2E 环境说明（与本批次无关）

本轮开始时全量 E2E 有 **68 条红**，根因是工作区里一份**未提交的前端改动**：登录页把协议勾选默认值从 `true` 改为 `false`

这些是**测试侧适配**，未改任何前端业务代码。
