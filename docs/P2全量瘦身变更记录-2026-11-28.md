## 第二步：跨端重复合并（工厂注入，避免 401）

### API 上提

`packages/shared/src/api/index.ts` 提供 **`createSharedAdminApi(http: SharedApiHttp)`**，把 auth / order / file 三组接口定义上提。
两端 `api/index.ts` 各自**注入本端 http** 后再按原名导出：

```ts
const sharedApis = createSharedAdminApi(http);   // 本端 @/utils/http，令牌前缀 / aud / 登出跳转都在这里
export const { authApi, orderApi, fileApi } = sharedApis;
```

原 `api/{auth,order,file}.ts` 变成一行转发 shim，**页面与测试的 import 路径零改动**。
这是防 401 的关键：没有做全局单例，客服端仍然用 `cs-token_` 前缀。

### 幂等工具

`packages/shared/src/idempotent.ts` 只放框架无关的键生成 / 复用 / 清空；
`useIdempotencyKey()` 的 `onScopeDispose` 生命周期封装留在两端薄适配层——**shared 不引入 vue 依赖**。
（首次尝试直接上提整份文件导致 `Cannot find module 'vue'`，三端 build 报错后按此边界重做。）

### 格式化函数收敛

| 原位置 | 改为 |
| --- | --- |
| `web-admin/views/report/sales.vue` 的 `maskPhone` | `import { maskPhone } from '@sent/shared'` |
| `web-user/views/order/detail.vue` 的 `maskPhone` | 同上 |
| `web-user/views/mine/{enterprise,invoices}.vue` 的 `fmtDate` | 同上 |
| `web-user/views/refund/apply.vue` 的 `STATUS_TEXT` + `statusText` | `statusLabel()` |
| 4 处手写 `Math.round(x * 100)` | `yuanToCent()`；价格页保留「不允许负数」的业务约束，只把换算交给 shared |

`web-admin/views/product/flash-sale.vue` 的 `STATUS_TEXT` 是**秒杀活动展示态**（不是订单状态），按范围保留。
