# 商城首页布局优化报告

- **日期**：2026-11-21
- **对象**：`web-user/src/views/home/index.vue`（商城端首页）
- **参照**：淘宝商城首页首屏（用户提供截图）
- **数据来源**：代码实测尺寸 + `GET /api/products` 接口实际返回值（当日 21:40 联调环境）
- **结论性质**：布局方案与改造清单，**尚未改代码**

---

## 一、结论先说

1. **核心病不是"不好看"，是"三栏比例错配"**：中栏被压到 726px，里面硬塞 260px 券卡 + 4 个 106px 瓦片，每个瓦片只有 106×108 —— 比淘宝右栏的促销块窄了 44%，所以标题必折行、价格必挤。
2. **右栏有约 130px 的"无效空白"**：`space-between` 把富余高度均摊成空白带，看着松、实际没信息。淘宝右栏用 2×2 网格天然填满，不存在这个动作。
3. **视觉重心打架**：券卡（260×183 橙色渐变 + 按钮）与 banner（橙红渐变 + 按钮）同为"主视觉 + CTA"，中间只隔 12px。淘宝首屏只有一个主视觉，其余全部让位。
4. **首屏文案与现实数据脱节**：4 个瓦片写 `¥151 / ¥182 / ¥329 / ¥89 起`，而接口实测 148 个 SKU 价格区间是 **10.00 ~ 40.00 元，中位 19.9 元**。数字差 4~10 倍，属于必须修的可信度问题。
5. **右侧用户卡（图 3）值得保留，但要做 8 处收敛**：它承担了"会员资产 + 快捷入口 + 企业采购"三重职责，是 B2B 场景的差异点，淘宝没有对应物，拆掉是损失。

## 二、首屏结构对照

| 区域 | 淘宝 | 我们 | 判断 |
|---|---|---|---|
| 左栏 | 分类面板，**标题是浅灰小字**，无实心色块；每行 4 个分类用 `/` 串起，8 行 ≈ 32 类 | 分类面板，标题是**深绿实心条 + 白字 15px**；每行 2 个分类，13 类占 7 行 | 标题权重过高；密度只有淘宝一半 |
| 中栏 | **单张主 banner**（约 660×270），文案 2 行大标题，右下角页码点，无按钮 | **两行**：券卡(260) + 4 瓦片(106×4) ｜ banner(200) | 两个主视觉抢戏，中栏被切成碎片 |
| 右栏 | **2×2 促销块**（每块约 190×130，多彩渐变 + 商品抠图） | **一张用户卡**（236 宽，拉伸至整栏高） | 淘宝右栏是"内容密度区"，我们是"个人区"；这是我们能差异化的地方 |

| 页面底 | 纯白底 + 发丝描边 | `#f5f5f5` 灰底 + 白卡浮起 | **不建议改**，这是全站语言 |

## 三、量化诊断

### 3.1 中栏被挤碎（最核心）

```
版心 1200
├ 左 210 ─┐
├ gap 14  │
├ 中 726 ─┤ = 1200 − 210 − 236 − 28
├ gap 14  │
└ 右 236 ─┘

中栏 726 内部：
券卡 260 + gap 10 + 瓦片区 456
瓦片区 456 = 4 × 106.5 + 3 × 10  →  单个瓦片 106.5 × 108
```

106px 宽要同时装下：14px 标题、11px 副标签、13px 价格、34px emoji。实拍截图里"定制队服/来图即做"已经开始两行排，再窄就会压字。

### 3.2 右栏 130px 空白带

用户卡实际内容高度约 256px（头像区 38 + 数据区 44 + 2×2 入口 84 + 企业采购 90），而 hero 高度约 386px。`justify-content: space-between` 把差额 **130px 均摊成 4 条空白带**。代码里 2026-11-21 的注释其实已经承认过这个改动（"原来内容贴顶…整块空白全堆在中间"），但均摊只是把洞摊薄了，没有消灭它。

### 3.3 左栏密度只有淘宝的一半

- 淘宝：4 类/行 → 同样 340px 高度能塞 32 个入口
- 我们：2 类/行，13 类只铺 7 行，且 `.cat-nav__list { flex: 1 }` 把 7 行强行拉伸到 386px → **每行 55px，比淘宝行高（约 42px）还松**，13 个入口占了一整屏的左侧。

### 3.4 视口 1024~1240 时用户卡直接消失

```css
@media (max-width: 1240px) { .side-card { display: none } }
```

这一刀把「我的订单 / 我的定制 / 我的收藏 / 我的足迹 / 在线客服 / 团购专区」六个人口全部砍掉。B2B 场景下"在线客服"是刚需入口，直接隐藏不如降级为两栏 + 卡片下移。

### 3.5 真实性待修

| 项 | 现状 | 实测 |
|---|---|---|
| 瓦片起价 | ¥151 / ¥182 / ¥329 / ¥89 | 全站 SKU 10.00~40.00，中位 19.9 |
| 券门槛 | 满 20 减 10 / 满 80 减 50 | 客单价中位 19.9，"满 80"需凑 4 件（需与后端券模板核对） |
| 商品主图 | 50% 为 null，走渐变+emoji 占位 | 淘宝首屏靠图，我们一半是占位块 |

## 四、建议版式（方案 C，推荐）

保持 1200 版心不动（改版心会牵动全站），只重排 hero 内部：

```
┌─ 208 ─┬────────────── 724 ──────────────┬─ 240 ─┐
│ 分类   │ ┌ 200 ┐ ┌─────── 512 ────────┐ │ 用户卡 │
│ (无实心│ │ 券卡 │ │   主 banner 250h   │ │ ≈300h │
│  色标题)│ │ 250h │ │  标题 26px / emoji  │ │ 不拉伸 │
│        │ └─────┘ └────────────────────┘ │       │
│ 13 类   │ ┌─173─┐┌─173─┐┌─173─┐┌─173─┐ │ ┌───┐ │
│ 7 行×36 │ │瓦片1││瓦片2││瓦片3││瓦片4│ │ │企业│ │
│        │ └─────┘└─────┘└─────┘└─────┘ │ │采购│ │
│ 查看全部│        76h 横条               │ └───┘ │
└────────┴───────────────────────────────┴───────┘
                     ↓
            猜你喜欢（4 列）
```

**关键三改**

1. **券卡与 banner 并排**，不再上下叠：banner 拿到 512px 宽 × 250 高（比例 2.05:1，接近淘宝 2.44:1），成为唯一主视觉；券卡降为 200 宽的"权益侧栏"，与 banner 等高于 250。
2. **4 个瓦片从 106×108 方块 → 173×76 横条**：标题与起价同行、emoji 靠右，信息不再折行。这是"学淘宝右栏的 4 块密度，但按我们的栏宽改成横向"。
3. **左栏去掉实心标题条**，改浅灰小字标签（`--sent-muted`，12px），行高固定 36px 不拉伸；13 类 7 行共 252px，加标题与"查看全部"约 322px，与中栏 338 基本齐平。

**备选方案**

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A 最贴淘宝 | 右栏改 2×2 促销块，用户卡下移到猜你喜欢上方通栏 | 最像淘宝，视觉最"满" | 用户卡从首屏右侧消失，违背你的保留要求 |
| B 最小改动 | 只把瓦片改横向 + 券卡缩到 200 | 改动 < 40 行，E2E 零风险 | 中栏仍是两行堆叠，banner 依然被压到 200 高 |
| **C 推荐** | 上表 | 主视觉唯一、三栏等高、用户卡保留在首屏 | 需改 hero 的 grid 与 banner 内部排版 |

## 七、不建议照抄淘宝的部分

| 淘宝做法 | 为什么不照抄 |
|---|---|
| 纯白底 + 发丝描边分隔 | 我们是灰底白卡体系，改这个等于全站回归，成本远大于收益 |
| 分类 `A / B / C / D` 四类一行 | 淘宝靠 hover 浮层承接二级分类；我们只有 13 个扁平类目，无二级数据，四类挤一行会让每个词只剩 40px，点击热区也不足 |
| 首屏塞 4 列商品瀑布 | 我们 50% 商品无主图，占位块密度一高就露出"半个站是渐变块"；保持 4 列大图更稳 |
| banner 用商品实拍抠图 | 无素材管线（`mainImage` 一半为 null），继续用 emoji，但要把 emoji 从"表情包感"压成"品类符号感"：缩到 96px、加径向暖光、降低不透明度到 .82 |

## 八、实施顺序（按项目铁律，分三步走）

**Step 1 — 只调栅格与瓦片形态（纯样式，无逻辑）**
- `home-hero` 栏宽、券卡+banner 并排、瓦片 106×108 → 173×76
- 验证：`npx playwright test e2e/home-entry-links.spec.ts`（4 个瓦片点击 + 券卡文案 + 会员日提示必须全绿）
- 验证：`npx playwright test e2e/category-result-page.spec.ts e2e/shop-nav-restructure.spec.ts`（`.cat-nav__item` 点击不回归）

**Step 2 — 用户卡 8 项收敛 + 未登录 CTA**
- 先写 E2E：未登录访问首页应出现「登录/注册」按钮；已登录显示 4 个入口与客服按钮
- 再改样式，最后跑全量 `e2e/`（含 5175 客服的 17 条用例，三端都要在监听）

**Step 3 — 数据真实性修复**
- 瓦片起价改为真实值或移除；券门槛与后端 `coupon` 模板对齐
- 由于涉及文案与可能的新接口调用，**这一步单独提交**，避免和视觉改动混在一个 commit 里

每步完成后跑：`mvn -o clean verify`（若涉及后端）+ 三端 `build`，再进下一步。

## 十、实施结果（2026-11-21 23:00 完成，方案 C 全量落地）

### 10.1 第一步 · 价格失真（P0）

**排查结论：假数据在前端，不在后端种子。**

- `home/index.vue` 的 `PROMO_TILES` 常量里写死 `price: '¥151 起'` 等四个值；
- 后端种子正常：148 个 SKU，零售价 **10.00 ~ 40.00 元**（中位 19.9）；
- 顺带核实券卡面额**是真的**：`/api/coupons/claimable` 返回 `5元无门槛 / 满20减10 / 满80减50` 三个模板，与页面文案一致，无需改。

**修法**：删掉写死价格，改为 `loadTilePrices()` 从 `/api/products` 按各自筛选条件（`size=100` 取全）计算**在售 SKU 最低零售价**。

| 瓦片 | 改前 | 改后（接口实测） |
|---|---|---|
| 定制队服 | ¥151 起 | **按件计价**（定制费按件结算，无商品报价可比，不编造数字） |
| 跑步装备 | ¥182 起 | **¥18.18 起** |
| 健身器材 | ¥329 起 | **¥16.27 起** |
| 球类专场 | ¥89 起 | **¥18.52 起** |

守护测试：`e2e/home-tile-prices.spec.ts` —— 瓦片起价必须落在接口算出的真实区间内，并断言四个瓦片文案仍在（E2E 点击锚点）。

### 10.2 第二步 · 首屏重排（1440 版心）

| 项 | 改前 | 改后 |
|---|---|---|
| 三栏 | 210 / 726 / 236 | **210 / 942 / 260** |
| 券卡 | 260×183（橙渐变，与瓦片同行） | **200×290**（白底橙描边，与 banner 并排） |
| banner | 934×200（4.7:1，宽横带） | **730×290（2.52:1）** |
| 四个瓦片 | 106×108 方块 | **227×76 横条**（标题/标签两行 + 起价与图标同行） |
| 右栏余高 | `space-between` 摊成空白带 | `flex-start` + 企业采购块 `margin-top:auto` 贴底吸收 |

### 10.3 第三步 · 用户卡 8 项收敛

| # | 改动 |
|---|---|
| 1 | 头像改中性暖色底 + 右下角 `LV3` 等级徽标（原品牌绿底白字「验」像"验证通过"标识） |
| 2 | 数字加千分位 + `tabular-nums`；0 值降灰（`.side-stat--zero`）；无数据显示「—」而非 0 |
| 3 | 2×2 入口去掉灰底灰边，改纯文字行，hover 用主色浅底 |
| 4 | 在线客服改**幽灵描边**，团购保留唯一实心 CTA |
| 5 | 等级色从橙色小字改为深绿徽标，不再与价格色撞 |
| 6 | 「企业采购？」→「企业采购」，说明压成一行「专票·账期·阶梯价」，按钮同行右对齐（省约 36px 高） |
| 7 | **新增未登录 CTA**「登录 / 注册」—— 会员数据缺失（token 过期、`/api/me` 失败）时的唯一出口 |

### 10.6 顶部搜索区对齐淘宝（2026-11-21 23:10）

**问题**：`.searchbox` 是 `flex:1; max-width:640px`，在 1440 版心下盒子紧贴 Logo 左侧、右侧空出一大块，整体视觉偏左，且比淘宝的搜索框短近四成。

**改法**：把 `.searchbar__inner` 从 flex 改成三列栅格，中间一列天然居中：

```css
.searchbar__inner {
  --searchbar-brand-col: 177px;   /* Logo 宽约 149 + 间距 28 */
  display: grid;
  grid-template-columns: var(--searchbar-brand-col) minmax(0, 1fr) var(--searchbar-brand-col);
  align-items: flex-start;
}
```

右轨道是一列**等宽空轨道**（无需额外 DOM），作用是让中间列严格居中；`.searchbox` 随之去掉 `max-width` 上限。

第一版实测（搜索框中心 vs 页面中心，单位 px）——「居中」达标：

| 视口 | 框宽 | 左留白 | 右留白 | 框中心 | 页面中心 |
|---|---|---|---|---|---|
| 1920 | 1086 | 177 | 177 | 960 | 960 |
| 1440 | 1054 | 177 | 177 | 720 | 720 |
| 1280 | 894 | 177 | 177 | 640 | 640 |

窄屏（≤900）退回 flex 两段式，避免三列把输入框挤没。

#### 10.6.1 二次调整：改为与首页中栏等宽（2026-11-21 23:20）

**反馈**：「有点太长了，跟中间领券加轮播图的长度加起来一样就行」。

第一版追求的是「居中且尽量长」，1054px 在那个语境下是合理的，但它把右轨道当成等宽空轨道用，与首页 hero 的实际三栏结构（分类 210 + 间距 14 | 中栏 | 间距 14 + 用户卡 260）没有关系，导致搜索框比中栏宽出一截、右边缘越过轮播图右边界，视觉上「压」在用户卡上方。

**改法**：把左右轨道从「对称空轨道」改成「与 hero 两侧栏对齐的实测值」，搜索框宽度就成了中栏宽度的自然结果，不需要额外写死任何宽度：

```css
.searchbar__inner {
  /* 左轨道 224 = 分类栏 210 + 间距 14；右轨道 274 = 用户卡 260 + 间距 14 */
  display: grid;
  grid-template-columns: 224px minmax(0, 1fr) 274px;
  align-items: flex-start;
}
@media (max-width: 1380px) and (min-width: 901px) {
  .searchbar__inner { grid-template-columns: 204px minmax(0, 1fr); }  /* hero 降两栏后对齐新中栏 */
}
```

实测（搜索框 `.searchbox` vs 首页主内容区 `.home-main`，单位 px）：

| 视口 | 搜索框宽 | 主内容宽 | 宽度差 | 左边缘差 |
|---|---|---|---|---|
| 1920 | 942 | 942 | 0 | 0 |
| 1440 | 910 | 910 | 0 | 0 |
| 1280 | 1044 | 1044 | 0 | 0 |

三个视口下宽度与左边缘偏移均为 **0**：搜索框左缘压住券卡左缘，右缘压住轮播图右缘。1380 以下 hero 变两栏（左轨随之收成 204），搜索框继续跟着新中栏走。

**为什么不用写死宽度**：若直接给 `.searchbox` 写 `width:942px`，1920/1280 会立刻失配（版心是 `max-width`，超宽屏不涨、窄屏不跌），且 hero 断点一改就要同步改两处。用栅格轨道表达「让开左栏、让开右栏」，宽度就是推导出来的，与 hero 天然同源。

**回归**：全量 E2E **145 passed / 0 failed（13.3 分钟）**，与上一轮条数一致；`vite build` ✓ 23.99s。头部是全站共用组件，故按全量跑而非抽样。

**已知遗留（本次未处理，与搜索框无关）**：390 视口本来就有约 56px 横向溢出 —— 来源是 `.topbar__links`（357px 装不下）与首页 hero 里 220px 固定的券卡，属移动端适配欠账，建议单独排一轮。
