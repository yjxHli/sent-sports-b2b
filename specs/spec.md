## 1. 背景与问题

森特体育用品当前的主营业务有两条并行的线：

1. **标品零售**：球类商品（足球、篮球、排球等）按型号、尺寸、材质、颜色销售，面向个人消费者与团体客户。
2. **UV 打印定制加工**：在球体表面打印客户提供的图案、LOGO、赛事标识。这既是"买球时加一道工序"，也是一项客户可以单独购买的加工服务（客户自备球来打）。

业务上还有一个不可忽视的特征：**客户结构是企业与个人混合**。学校、俱乐部、赛事组委会、经销商这类客户会批量采购、要比价、要合同、要发票、要账期；个人客户则会比价、看会员权益、问客服。

现状的问题集中在四处：

| 问题 | 具体表现 |
| --- | --- |
| 报价靠人 | 一客一价、批量阶梯价、企业协议价散落在销售员手里，同一客户不同销售员报出不同价，事后无法追溯依据 |
| 定制靠微信 | 图稿通过聊天工具传来传去，审核意见口头传达，驳回后重传版本混乱，出问题无法界定责任 |
| 账期靠表格 | 哪些单已回款、哪些逾期、谁该催款，靠财务手工表格，销售员不知道自己的客户欠多少 |
| 客户归属不清 | 客户被谁开发、业绩算谁的、离职后客户归谁，缺少可查的流转记录 |

本系统的目标是把这些"靠人、靠聊天工具、靠表格"的环节固化进系统，同时给个人客户一个能自己下单、自己看进度、自己找客服的商城。

> **范围克制原则**：本系统是"销售与定制履约系统"，不是 ERP。凡是不能直接服务于"卖出去、印准确、收得回"的功能，一律不做（见第 12 章）。

## 2. 产品定位与目标

### 2.1 一句话定位

一套同时支撑"标品零售 + 定制加工 + 企业账期"的体育用品经营系统，用户端负责卖货与自助服务，管理端负责定价、履约、审图、对账与客户经营。

### 2.2 业务目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 定价有据可依 | 每一笔订单行都能追溯"用了哪条价格规则"，价格争议可当场举证 |
| G2 | 定制可管可追 | 每张定制单的图稿版本、审核意见、驳回原因、开产时间全程留痕 |
| G3 | 账期不失控 | 应收、已回、逾期在同一张表里，逾期客户自动受限 |
| G4 | 客户归属清晰 | 客户与销售员的绑定关系可查、可改派、改派有原因有记录 |
| G5 | 服务可衡量 | 客服首响时长、会话量、审图时效、发货及时性可统计 |

### 2.3 设计原则（贯穿全文的取舍标准）

1. **状态只由事实驱动**：订单是否已付款，只认支付回调这一件事，任何界面都不允许"看起来付了就当付了"。
2. **金额与库存只增流水、不改历史**：价格改了下过的单不受影响，库存变动必须有据可查。
3. **规则写死在文档里，不写死在人的脑子里**：凡是"看情况"的地方，本文档必须给出明确规则。
4. **越权不可见，而非不可点**：没有权限的数据不应出现在列表、导出、搜索建议里。
5. **实时用于人，异步用于事**：客户沟通走实时会话保证体验；业务流转（审图、退款、回款）靠状态与待办推进，不靠聊天记录当凭据。

## 3. 用户与角色

### 3.1 用户端角色

| 角色 | 定义 | 获得方式 | 关键差异 |
| --- | --- | --- | --- |
| 游客 | 未登录访问者 | 直接访问 | 可浏览商品与零售价，不可下单、不可咨询、不可看会员价 |
| 普通用户 | 已注册的个人客户 | 手机号注册 | 可下单、可发起会话、累计成长值 |
| VIP 用户 | 达到等级门槛或经人工授予的个人客户 | 成长值自动升级 / 管理员授予 | 会员价、积分、专属客服优先、新品优先购、部分专属商品 |
| 企业客户 | 已完成企业认证的客户 | 提交资质，管理员审核通过 | 协议价、账期与信用额度、合同与开票、专属销售员跟进 |

> 企业客户与 VIP 不是互斥关系。企业客户账号同样有等级（由回款额决定），但企业客户的核心差异来自"协议价 + 账期"，等级差异来自"折扣与优先权"。两者叠加时的取价规则见 6.1。

### 3.2 管理端角色与职责（6 个角色，不新增）

| 角色 | 核心职责 | 明确不管的事 |
| --- | --- | --- |
| 超管 | 账号与角色配置、权限维护、系统参数（超时时间、审图时限、等级门槛）、全量数据、操作日志审计 | 不参与日常接单（可手动介入） |
| 销售主管 | 客户分配与改派、团队业绩看板、协议价审批、逾期客户跟进督办 | 不做库存操作、不做退款打款 |
| 销售员 | 跟进归属客户、代客下单/报价、催款、售后协调、查看自己客户与订单 | 不能改别人的客户、不能改价格体系、不能审核退款 |
| 财务 | 应收台账、回款登记与核销、退款审核、发票与合同归档、对账 | 不改商品与库存、不改客户归属 |
| 仓管 | 库存初始化入库、报损、盘点、按订单行发货、库存预警处理 | 看不到客户成交价与联系方式（仅收货信息） |
| 客服 | **在线实时接待咨询**、协助下单、**定制图稿审核**、售后受理与转接 | 不改价格、不改订单金额、不审核退款（可发起） |

> **定稿说明**：审图由客服兼任，不新增"设计/美工"角色。理由是审图本质是"与客户把需求问清楚"，与客服职责同源，且避免权限体系膨胀。生产可行性异议由客服转仓管确认。

### 3.3 客户归属关系

- 每个注册用户（个人或企业）都有**唯一归属销售员**，注册时自动分配，主管可改派。
- **分配规则**：在该角色在职人员中，取"当前名下客户数最少"的人；并列时按员工编号顺序取第一个。企业客户优先分配给销售主管指定的人员。
- 归属决定三件事：业绩归属、数据可见范围、服务责任人。
- 改派必须填写原因，记录操作人与时间；**改派只影响改派之后的订单业绩，不改历史**。
- 销售员离职时，主管需按销售员筛选后批量改派其名下客户。

## 4. 关键概念与术语

| 术语 | 定义 | 说明 |
| --- | --- | --- |
| SPU / 商品 | 一款球的概念层，如"森特比赛级 5 号足球" | 承载标题、卖点、图集、分类、详情 |
| SKU / 规格 | SPU 下的可售最小单位，由尺寸 × 材质 × 颜色组合而成 | 库存、价格、条码挂在 SKU 上 |
| 标品 | 无需加工的现货商品 | 可直接下单发货 |
| 定制项 | 挂在标品上的加购服务（买球 + UV 打印） | 与标品同单，但走独立审核流 |
| 定制服务 | 独立售卖的服务商品（客户自备球来打） | 无实物库存，有工期 |
| 定制单 | 一次定制加工的业务凭据 | 与订单行一对一关联，独立状态机 |
| 图稿 | 客户上传的待打印文件 | 需版本管理，驳回后重传生成新版本 |
| 零售价 | 商品的基础标价 | 所有价格的锚点 |
| 会员价 | 按 VIP 等级折扣率算出的价格 | 与等级绑定 |
| 协议价 | 与企业客户签约约定的价格或折扣 | 可一客一价，可带有效期 |
| 阶梯价 | 按单行购买数量分段的优惠价 | 如 1-9 个原价、10-49 个 9 折 |
| 一客一价 | 针对某客户 + 某 SKU 的专属成交价 | 优先级最高 |
| 底价 | 某 SKU 允许成交的最低价格 | 低于底价必须审批 |
| 成长值 | 用于升级的有效消费累计（以已支付/已回款为准） | 与积分区分，成长值不消耗 |
| 积分 | 可消耗的权益凭证，仅用于抵现 | 规则见 6.4 |
| 信用额度 | 企业客户可赊账的上限 | 下单占用，核销回款后释放 |
| 账期 | 约定的付款期限，如月结 30 天 | 到期未付即逾期 |
| 回款 | 客户实际付款到账并核销到订单 | 与"下单"是两件事 |
| 预占 | 下单后锁定但未出库的库存 | 超时释放 |
| 包裹 / 发货单 | 一次发货动作及其物流信息 | 一个订单可有多个包裹，按订单行拆分 |
| 客服会话 | 客户与客服之间的实时对话线程 | 有排队、接入、转接、结束四个阶段 |
| 售后单 | 一次退款或退货的业务凭据 | 与订单解耦，独立处理 |

## 5. 业务全景

### 5.1 主流程（个人客户买标品）

浏览商品 → 选规格 → 加购/直接购买 → 填收货信息 → 确认价格（含会员价与可用积分）→ 提交订单（预占库存）→ 模拟支付 → 支付回调确认 → 仓管按行发货 → 客户确认收货 → 订单完成 → 成长值与积分入账。

### 5.2 主流程（客户定制）

选标品（或选定制服务）→ 勾选 UV 打印 → 填写定制要求（打印位置、面数、数量、说明）→ 上传图稿 → 提交订单 → 支付 → 客服审图 → 通过则排产，驳回则补充说明并重传 → 审核通过 → 排产 → 生产 → 完工 → 按行发货（可与同单标品分开发）→ 收货。

> **重要**：定制单在"审核通过"之前，该订单行不可发货；审核驳回期间订单挂起，客户可主动取消（未排产）。

### 5.3 主流程（企业客户采购）

注册 → 提交企业资质 → 管理员审核 → 授予协议价与账期 → 销售员报价 → 客户确认 → 下单（占用信用额度）→ 发货 → 财务登记回款并勾选订单核销 → 额度释放 → 成长值按核销金额累计。

### 5.4 主流程（客服）

客户在商品页、订单页或悬浮入口发起咨询 → 系统匹配在线客服并接入 → 双方实时对话（可发图片、商品卡、订单卡）→ 需要他人协助时转接 → 问题解决后结束会话；无人在线时进入排队并可留言。

## 6. 核心业务规则

> 本章是全文档最重要的部分。凡此处未定义的判断，一律不得在实现时自行发挥。

### 6.1 取价规则

#### 6.1.1 取价顺序（命中即止，默认不叠加）

对每一个"客户 × SKU"组合，按下表自上而下匹配，命中即采用，不再向下：

| 优先级 | 价格类型 | 适用对象 | 说明 |
| --- | --- | --- | --- |
| 1 | 一客一价 | 指定客户 + 指定 SKU | 由销售主管或超管设定，可设有效期 |
| 2 | 协议价 | 企业客户 | 按签约折扣率作用于零售价，可带合同有效期 |
| 3 | 阶梯价 | 所有客户 | 按该 SKU 单行数量分段，命中区间取该区间价 |
| 4 | 会员价 | VIP 用户 | 按等级折扣率作用于零售价 |
| 5 | 零售价 | 所有客户 | 兜底 |

#### 6.1.2 冲突与防倒挂（不取低，只认优先级）

- **严格优先级，命中即止**：按 6.1.1 顺序，先命中的价格即为成交价，**不再向下比较，也不与后面的价格取低**。
- **协议价生效后不再叠加阶梯折扣**：企业客户一旦命中协议价，即按协议价成交，**不参与阶梯量价**。原因是协议价通常已是接近成本的折扣，若再叠阶梯会导致售价低于成本（倒挂）。
- **不支持"折上折"作为默认行为**：仅当合同明确约定"协议价基础上再享阶梯折扣"时，才启用叠加模式，且该模式需在客户档案上显式开启，并受底价强制校验。
- **会员价与阶梯价同时具备时，取阶梯价**（阶梯优先于会员），不再取低。这样"买得越多越便宜"的直觉成立，也避免 VIP 大单反而比普通客户贵。
- **一客一价一旦设定，即为最终价**，不参与任何其他优惠。
- **底价是最后一道闸**：任何取价结果若低于该 SKU 的底价，**禁止下单**；确需成交由超管审批放行，审批记录必须落到订单。
- **倒挂告警**：若某次取价结果低于该 SKU 的成本价，即使未低于底价，也需在管理端产生一条"售价低于成本"告警，供定价复核。
- 定制服务费默认**不参与**会员折扣与阶梯价，可参与协议价（默认参与）。
- 运费不计入折扣计算，单独计算与显示。

> **为什么改**：原文"取两者中更低者"与 6.1.1 的"命中即止、不再向下"自相矛盾，且会出现"企业协议 5 折 + 阶梯 4.5 折 → 4.5 折"的亏本单。改为严格优先级后，规则唯一、可解释、可审计。

#### 6.1.3 价格快照

- 订单提交时，为每一行记录：单价、数量、金额、取价来源（一客一价/协议价/阶梯价/会员价/零售价）、命中的规则标识、优惠分摊金额。
- 下单后商品调价、等级变动、协议到期，**一律不影响已提交订单**。
- 订单详情页对客户展示"成交价"，不展示取价来源；管理端展示完整来源，供对账与争议处理。

### 6.2 库存规则

#### 6.2.1 库存口径

| 口径 | 含义 |
| --- | --- |
| 实物库存 | 仓库里实际存在的数量 |
| 预占量 | 已下单未支付、已支付未发货所锁定的数量 |
| 待检量 | 退货回补但未质检、不可销售的数量 |
| 可售库存 | 实物库存 − 预占量 − 待检量 − 冻结量 |

**对外展示与下单校验，一律使用"可售库存"。**

#### 6.2.2 库存变动时点

| 事件 | 库存动作 |
| --- | --- |
| 提交订单 | 即时预占（锁定），预占有效期默认 30 分钟（可配置） |
| 支付回调成功 | 预占转为已占用（账面扣减），不再重复扣 |
| 超时未支付 | 订单自动取消，释放预占 |
| 用户主动取消（未支付） | 立即释放预占 |
| 发货出库 | 按包裹扣减实物库存，对应预占清零 |
| 退款审核通过且货已退回 | 标品入"待检"，质检合格后回补可售；不合格入次品/报损 |
| 定制件退货 | 不回补可售（已打印，不可二次销售），只能报损或另作处理 |

#### 6.2.3 边界处理（必须实现）

1. **超时与回调赛跑**：订单已超时取消，但支付回调随后到达 → 订单**不复活**，自动生成退款单并按"仅退款"流程处理，同时通知客户与财务。这是最容易出错的地方，必须写死。
2. **最后一件并发**：同一 SKU 仅剩 1 件时，两个客户同时提交，只能一个成功；失败方明确提示"该规格库存不足"，不允许生成待支付订单。
3. **库存为 0 时**：商品详情页显示"暂时缺货"，提供"到货提醒"按钮（订阅后到货时发站内信），不允许加购。
4. **商品下架但仍在购物车**：结算时拦截并提示"该商品已下架"，可一键移除。
5. **下单后商品被下架**：已支付订单不受影响，正常履约。
6. **负库存**：任何情况下不允许出现负的可售库存。
7. **库存不足的补货方式**：由仓管在后台执行"手工入库"（填数量、原因、备注），不做采购单流转。

### 6.3 会员与等级

#### 6.3.1 等级结构（三级，定稿）

| 等级 | 成长值门槛 | 折扣率 | 积分倍率 | 其他权益 |
| --- | --- | --- | --- | --- |
| 普通会员 | 0 | 无折扣 | 1 倍 | 正常下单 |
| VIP1 | 累计成长值 ≥ 2,000 | 98 折 | 1 倍 | 专属客服优先、新品提前 3 天 |
| VIP2 | 累计成长值 ≥ 10,000 | 95 折 | 1.2 倍 | 专属客服优先、新品提前 7 天、部分专属商品 |

- 只保留三级，不做更多档位。门槛与折扣率可在系统参数中调整，但档位数量固定。
- "专属商品"指可设置最低可见等级（VIP2）的商品；未达等级用户访问时提示"该商品暂未对您开放"，不返回价格与库存。

#### 6.3.2 成长值与升降级

- 个人客户：按**已支付且未退款**的订单实付金额累计（1 元 = 1 成长值）。退款成功后扣回对应成长值。
- 企业客户：按**已核销的回款金额**累计，而非下单金额。目的是避免赊账虚增等级。
- 成长值随消费增加，随退款扣回，除此之外不减少。
- **不启用自动降级**：不做滚动周期结算，不设保级期。等级只升不降；退款扣回成长值后若低于门槛，次日按当前成长值重算（仅此一种回落情形）。
- **降级只能人工执行**：由超管操作，必须填写原因并留痕。

#### 6.3.3 人工授予

- 超管/销售主管可对指定客户授予或调整等级，必须填写原因，设定有效期（可永久）。
- 人工授予的等级优先于自动成长等级，到期后回落到按成长值计算的等级。
- 所有授予/调整记录进入操作日志，可在客户详情页查看历史。

### 6.4 积分

- 获取：订单完成后按实付金额发放（1 元 = 1 积分 × 等级倍率），运费不计。
- 消耗：**仅用于下单抵现**，100 积分 = 1 元，单笔订单最多抵扣商品金额的 30%。不做积分商城、不做积分兑换商品。
- 扣回：退款成功后扣回该订单产生的积分；积分已被消耗导致余额不足时记为负积分，后续消费优先抵扣。
- 有效期：12 个月滚动过期，过期前 7 天站内信提醒。
- 积分明细需可查：获得、消耗、过期、扣回，逐条带来源单据。

### 6.5 定制（UV 打印）规则

#### 6.5.1 两种入口

| 入口 | 场景 | 计费 | 库存 |
| --- | --- | --- | --- |
| 标品加购定制项 | 买球时勾选 UV 打印 | 商品价 + 定制服务费 | 标品 SKU 正常预占 |
| 独立定制服务商品 | 客户自备球，仅购买打印服务 | 仅服务费 | 无实物库存，按工期排产 |

#### 6.5.2 定制计费（定稿）

服务费 = 单价（由面数与数量阶梯决定）× 数量。

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 打印面数 | 单面 / 双面 / 全包 | 面数越多单价越高，系数由后台配置 |
| 数量阶梯 | 如 1-9 / 10-49 / 50-199 / 200+ | 数量越大单价越低，按该定制服务商品配置 |

- **不设颜色系数**：彩色与单色同价，避免前端试算与后端结算不一致。
- 不设加急服务，交期统一按标准工期展示。
- 服务费金额在下单时快照，后续调价不影响已下单订单。

#### 6.5.3 图稿要求

- 格式：JPG / PNG / PDF / AI / PSD
- 单文件大小上限 50MB，单张定制单最多 10 个附件
- 必须勾选"我确认拥有该图案的使用权，因版权产生的纠纷由我方承担"
- 图稿需保留完整版本历史，每次重传生成新版本（V1、V2…），旧版本只读不可删
- 图稿保留期：订单完成后保留 24 个月（可配），到期归档

#### 6.5.4 审核规则

- 客服在 **24 小时**内完成首次审核，超时自动提醒客服与其主管（时限可配）
- 审核结论只有两种：通过 / 驳回
- 驳回必须选择原因分类（图稿分辨率不足 / 含违规内容 / 尺寸与打印区域不符 / 版权存疑 / 其他）并填写说明
- 驳回后可重传，**最多 3 次**，第 4 次转人工介入（主管处理）
- 审核通过即锁定图稿版本，后续不可替换；如需修改须走"变更申请"，可能影响交期与费用
- 无图稿不得提交定制单

#### 6.5.5 交付与退款

- 交期 = 标准生产周期 + 物流时间，下单时向客户明示"预计发货日"
- 开产前（审核通过但未排产）：客户可取消，全额退款（含服务费）
- 已排产/生产中：不可取消；仅在质量问题时可申请重做或退款，需仓管与主管双确认
- 定制件原则上不支持"七天无理由"，此规则需在下单页明示并由客户勾选确认

### 6.6 订单规则

#### 6.6.1 订单状态（主状态，单一维度）

| 状态 | 含义 | 可进入的前置状态 |
| --- | --- | --- |
| 待付款 | 已提交，库存已预占 | 新订单 |
| 待发货 | 已支付，尚未发出任何包裹 | 待付款 |
| 部分发货 | 已有包裹发出，仍有未发数量 | 待发货 / 部分发货 |
| 待收货 | 全部数量已发出，等待确认收货 | 待发货 / 部分发货 |
| 已完成 | 全部包裹确认收货，或超时自动确认 | 待收货 |
| 已取消 | 未支付取消 / 超时取消 | 待付款 |
| 已关闭 | 全部退款完成后的终态 | 待发货 / 部分发货 / 待收货 / 已完成 |

> **设计说明**：支付状态、定制状态、售后状态**不与订单主状态混在一起**。用四个独立维度描述一张订单，可避免状态爆炸与"一个状态表达两件事"的歧义。

#### 6.6.2 四个独立维度

| 维度 | 取值 |
| --- | --- |
| 订单主状态 | 待付款 / 待发货 / 部分发货 / 待收货 / 已完成 / 已取消 / 已关闭 |
| 支付状态 | 未支付 / 支付中 / 已支付 / 部分退款 / 全额退款 |
| 定制状态 | 无定制 / 待提交图稿 / 待审核 / 审核驳回 / 审核通过 / 生产中 / 已完工 |
| 售后状态 | 无售后 / 售后申请中 / 退货中 / 已退款 / 已拒绝 |

管理端列表需支持按维度组合筛选，例如"部分发货 + 定制审核通过 + 未回款"。

#### 6.6.3 支付规则

- 支付方式：一期为**模拟支付**，提供"模拟支付成功 / 模拟支付失败 / 模拟用户取消"三种结果。
- 支付结果**只能由支付回调写入**。用户在前端点"我已支付"不改变任何状态，仅提示"正在确认支付结果"。
- 回调必须携带业务订单号与支付流水号，系统需校验金额一致；金额不一致时拒绝并告警，不得自动改单。
- 回调需支持**重复通知**（幂等）：同一流水号重复到达，只处理一次，返回成功。
- 支付流水需独立存储：流水号、订单号、金额、渠道、请求时间、回调时间、结果、原始报文。
- 支付中状态超过 5 分钟无回调结果，前端展示"支付结果确认中"，并提供"刷新"与"联系客服"。

> 虽然一期是模拟支付，但**流水、回调、幂等、金额校验、退款原路返回**这套逻辑必须按真实业务做，以便将来替换为真实渠道时业务代码不改。这是本项目的硬性约束。

#### 6.6.4 订单取消与超时

- 待付款订单超过 30 分钟（可配）未支付，系统自动取消并释放预占。
- 用户在待付款状态可主动取消，立即释放预占。
- 已支付订单不可由用户直接取消，需走退款流程。
- 管理员可在未发货状态下关闭订单（需填写原因），触发未发部分全额退款。

#### 6.6.5 发货与收货（支持按行拆单）

- **发货以"包裹"为单位**，一个包裹可包含一个或多个订单行的数量，也可只发某个订单行的部分数量。
- **必须支持同一订单的标品与定制件分开发货**：标品先发，定制件完工后另发。
- 未发完的订单处于"部分发货"，全部数量发出后转"待收货"。
- 发货录入：物流公司、运单号、发货时间、备注；一期不接物流轨迹查询，仅展示单号。
- 客户可对已发包裹逐个确认收货；**全部包裹确认后订单完成**。
- 最后一个包裹发货后 15 天未确认，系统自动确认收货（可配），提前 3 天站内信提醒。
- 已发货的订单行如需退款，需走退货流程；未发货的订单行可仅退款。

### 6.7 退款与售后

#### 6.7.1 可退性判定

| 订单状态 | 定制情况 | 可退性 |
| --- | --- | --- |
| 待付款 | 任意 | 直接取消，不产生退款单 |
| 待发货 | 无定制 / 定制未排产 | 可申请仅退款，无需退货 |
| 待发货 | 定制已排产或生产中 | 不可退（质量问题除外，需双人确认） |
| 部分发货 | 未发货行 | 仅退款 |
| 部分发货 | 已发货行 | 退货退款 |
| 待收货 | 任意 | 退货退款，需退回货物 |
| 已完成 | 7 天内 | 退货退款（定制件除外） |
| 已完成 | 超过 7 天 | 不可申请，只能走客服特殊处理 |

#### 6.7.2 退款金额计算

- 按订单行**实付金额**退回，含该行分摊的优惠金额。
- 部分退款时，优惠按行金额比例分摊，不允许"退掉优惠最大的那件"造成优惠套利。
- 运费规则：未发货全额退运费；已发货且整单退，运费不退（除非责任在商家）。
- **部分退货导致不满包邮门槛的，不补扣运费**（定稿）。
- 使用积分抵扣的部分，退款时**优先退回积分**；积分已过期则按等值金额退回。

#### 6.7.3 退款流程

客户申请（选原因、上传凭证、填退款金额）→ 客服受理并核对 → 财务审核 → 通过则发起模拟退款回调 → 退款成功 → 更新支付状态、扣回成长值与积分、回补库存（标品）。

- 退款审核时限：48 小时内给出结论（可配），超时提醒。
- 驳回必须填写原因，客户可再次申诉（一次）。
- 退款到账时间：模拟环境下即时，需向客户展示"退回原支付账户"。
- 财务打款确认与系统退款状态必须一致，禁止"线下已退但系统没记录"。

### 6.8 账期、应收与回款（核心能力，保持简单）

#### 6.8.1 授信

- 企业客户提交资质（营业执照、开票信息、联系人）→ 销售主管初审 → 财务终审 → 授予账期天数（如月结 30 天）与信用额度。
- 授信需有有效期，到期需复审；未授信的企业客户只能预付。

#### 6.8.2 额度占用与释放

- 下单时按订单应付金额占用额度；额度不足时禁止下单，提示"信用额度不足，请联系您的销售员"。
- 回款核销后释放对应额度；退款后释放对应额度。
- 逾期未回款的订单持续占用额度。

#### 6.8.3 逾期

- 超过账期未回款即标记逾期，逾期当天通知销售员与财务，逾期 3 天通知销售主管。
- 逾期客户自动冻结"账期下单"能力，只能预付；解除冻结需财务操作。
- 逾期记录进入客户档案，作为后续授信调整依据。

#### 6.8.4 回款登记与核销（只做这一件事）

流程：财务登记回款 → 勾选订单核销 → 释放信用额度 → 应收台账更新。

- 登记字段：客户、回款金额、到账日期、银行流水号、备注。
- 一笔回款可勾选多张订单核销，金额按勾选顺序分配；**不支持预收款**，回款金额不得超过所选订单的未回款合计。
- 一张订单可分多次回款，每次核销后累加"已回款金额"。
- 登记错误可执行"冲销"（反向撤销），需填写原因并留痕，冲销后额度回退。
- **不做**：预收款账户、退款冲抵应收、按账龄自动分摊。

### 6.9 开票与合同（保留结构，简化流转）

- 开票：订单完成后客户提交抬头、税号、类型（普票/专票）、邮箱 → 财务在后台标记"已开票"并上传发票 PDF → 客户可在"我的发票"下载。
- 一张订单对应一张发票，**不做合并开票**，不对接任何税控系统。
- 合同：企业客户上传合同扫描件，记录合同编号、签约日期、有效期、约定折扣；到期前 30 天提醒销售员续签。
- 合同仅作附件归档，不做电子签、不做条款审批流。

### 6.10 在线客服会话规则（实时）

#### 6.10.1 接待与分配

- 客户在商品详情、订单详情或悬浮入口发起咨询，进入**实时会话窗口**，双方消息即时送达。
- 客服需先处于"在线"状态才可接待；主管可设接待上限（默认同时 10 个进行中会话）。
- **分配规则**：从"在线且未达接待上限"的客服中，取当前进行中会话数最少者；并列时按员工编号顺序取第一个。
- **固定绑定**：同一客户优先分配给其历史客服（该客服在线时）；不在线则按上述规则分配。
- **排队**：无可用客服时客户进入排队，页面展示排队人数与预计等待时长；等待期间可留言，客服上线后收到提醒。
- **工作时间**：客服工作时间可配（默认 9:00–18:00）。非工作时间内客户发起咨询，直接提示"当前非客服工作时间，可留言，我们将在工作时间优先回复"。
- VIP 与企业客户优先分配给"专属客服组"（主管配置名单），排队优先级高于普通客户。

#### 6.10.2 会话状态

| 状态 | 含义 | 进入方式 |
| --- | --- | --- |
| 待接入 | 已发起或排队中，尚无客服接待 | 客户发起且无空闲客服 |
| 进行中 | 客服已接入，双方可实时收发 | 分配成功 / 客服手动接入 |
| 已结束 | 会话终止 | 客服结束 / 客户结束 / 超时自动结束 |

- 同一客户同一时间只允许**一个进行中会话**；再次发起咨询并入现有会话（不新建）。
- 已结束会话不可重开；客户可新建会话，历史会话可查。
- 会话结束后客户仍可留言，留言作为该客户的新待接入会话进入队列。

#### 6.10.3 消息能力

- 文字、图片（图稿、实物照片、付款凭证）、商品卡片、订单卡片
- 快捷回复（客服个人话术 + 主管维护的公共话术）
- 转接：转给指定客服或角色，需填写转接原因；接收方接手后原客服退出，客户侧提示"已为您转接"
- 会话标签（咨询/报价/定制/售后/投诉），用于检索与统计
- 未读提醒：客户侧与服务侧均有未读红点；客服侧可见客户是否已读自己发出的消息，客户侧不显示"已读"回执
- 会话与客户、订单、定制单关联，侧栏一点即见上下文
- **不做**：语音/视频通话、群聊、消息撤回、机器人自动应答、满意度评分

#### 6.10.4 实时性与可靠性（必须成立）

- **送达时效**：正常网络下，消息 1 秒内到达对端。
- **断线重连**：网络中断恢复后自动重连，并补拉断线期间未收到的消息，按发送顺序展示。
- **不丢不重**：同一条消息在重连后不得重复展示；每条消息有唯一标识与发送顺序。
- **发送状态**：消息展示"发送中 / 已送达 / 发送失败"，失败可点击重发。
- **离线可感知**：客服离线或网络异常时，客户侧必须明确提示"客服暂时离线，可留言"，不得让客户误以为对方已读不回。
- **顺序一致**：双方看到的会话顺序一致，不得出现消息跳序。

#### 6.10.5 时效与约束

- **首响时限**：工作时间内 5 分钟内首次回复，超时提醒客服与其主管；该指标进入客服看板。
- **会话超时**：双方 30 分钟无新消息，自动结束并提示客户可重新发起（可配）。
- 客户 5 分钟无新消息时，客服侧可主动结束会话，需选择结束原因（已解决/客户离开/无效咨询）。
- 未登录用户不可发起会话（PC Web 场景下先登录）。
- 会话记录保留 36 个月，客服不可删除消息。
- 客服不可见客户完整支付信息（仅可见订单号、金额、状态）。

### 6.11 审批与留痕

| 事项 | 审批人 | 是否必须填原因 |
| --- | --- | --- |
| 低于底价成交 | 超管 | 是 |
| 一客一价设定/修改 | 销售主管 | 是 |
| 企业授信与额度调整 | 财务（主管初审） | 是 |
| 客户归属改派 | 销售主管 | 是 |
| 人工授予/降低会员等级 | 超管 | 是 |
| 退款审核 | 财务 | 驳回必填，通过可选 |
| 定制单开产后取消 | 主管 + 仓管 | 是 |
| 订单关闭（未发货） | 销售主管 | 是 |
| 库存报损 | 仓管（超阈值需主管） | 是 |
| 回款冲销 | 财务 | 是 |

所有审批动作进入操作日志：谁、何时、对什么对象、改前值、改后值、原因。

## 10. 边缘场景清单（必须在设计与验收中覆盖）

### 10.1 价格

1. 客户在购物车停留期间等级升级，结算时按结算时刻等级取价，并在页面提示价格已更新。
2. 一客一价到期当天仍可下单，次日恢复原价。
3. 协议价与阶梯价同时命中时，**按协议价成交，阶梯不生效**；页面只显示最终价，不展示被忽略的阶梯价，避免客户误解。
3a. VIP 客户大批量购买，命中的是阶梯价而非会员价，页面标注"阶梯价"而非"VIP 价"，避免客户质疑"为什么不是会员价"。
3b. 成交价低于成本价（但未低于底价）时，允许下单，同时在管理端生成"售价低于成本"告警。
4. 取价后低于底价 → 拦截，提示联系销售员，不允许自助下单。
5. 客户手动输入数量跨越阶梯区间，价格实时重算，不得出现"按低价算但只买少量"。
6. 定制服务费不参与会员折扣，订单总额需说明"服务费不享折扣"，避免客户认为算错。
7. 退款后重新下单，不保留原订单的优惠价。

### 10.2 库存

8. 超时取消与支付回调同时发生（见 6.2.3 第 1 条）。
9. 两个客户同时抢最后一件。
10. 发货时发现实物少于账面（盘亏），需支持"发货失败并调整库存"，订单转异常并通知客户。
11. 客户下单后商品被下架，订单正常履约。
12. 退货回补的球已使用过，质检不合格 → 入次品库，不回补可售。
13. 定制件退货不回补，只能报损。
14. 缺货商品客户点了"到货提醒"，补货入库后系统向其发站内信，一次性提醒，不重复推送。

### 10.3 订单与支付

15. 支付回调金额与订单金额不一致 → 拒绝入账并告警，人工介入。
16. 同一支付流水回调多次 → 幂等，只入账一次。
17. 客户在支付页关闭窗口后再回来 → 订单仍在待付款倒计时内，可继续支付。
18. 客户重复点击"支付" → 只允许一个支付请求在处理中。
19. **一个订单含标品与定制件**：先发标品，订单转"部分发货"，客户可先确认该包裹；定制件完工后另发，全部发完转"待收货"。
20. 客户只确认了部分包裹 → 订单仍为"部分发货"或"待收货"，直到全部包裹确认才完成。
21. 发货后客户申请退款 → 需先退货，退款金额不含运费（除商家责任）。
22. 订单已完成超过 7 天再申请退款 → 拒绝并引导联系客服。
23. 企业客户已回款的订单退款 → 退款退回客户，**不回改应收台账**，由财务线下处理差额。

### 10.4 定制

24. 客户下单未上传图稿 → 订单可支付但定制单停在"待提交图稿"，客服需主动催。
25. 客户支付后长期不传图稿（如 15 天）→ **转人工客服跟单**，不做自动取消与自动退款。
26. 图稿分辨率不足 → 驳回，客户重传，版本号递增，旧版本保留。
27. 驳回 3 次后第 4 次 → 转主管，客服不可再审。
28. 审核通过后客户要求改图 → 走变更申请，可能重新计费与延期，需客户确认。
29. 打印位置与球体接缝冲突 → 客服转仓管确认，不得直接驳回而不解释。
30. 客户自备球寄来但球体材质不适合 UV 打印 → 收货后检测不合格，需退件并退服务费。
31. 定制件质量问题 → 重做优先于退款，重做不额外收费但要记录成本。

### 10.5 会员与积分

32. 客户退款后成长值扣回，可能低于当前等级门槛 → **当日不降级**，次日按成长值重算；仍不满足需超管人工确认是否降级。
33. 积分抵扣后整单退款，积分优先退回；若积分已过期，按等值金额退回。
34. 人工授予等级到期当天，客户正在下单 → 以下单时刻等级为准。
35. 客户被授予 VIP2 后立即看到专属商品，但历史浏览记录不应泄露专属商品。

### 10.6 客户与归属

36. 销售员离职，其客户批量改派，未完成订单的业绩归属需明确（建议：已支付订单业绩仍归原销售员，未成交客户归新销售员）。
37. 同一手机号既注册个人又申请企业 → 需支持"个人账号升级为企业账号"，历史订单保留。
38. 企业客户更换对接人 → **一期不支持子账号**，需原账号移交或由销售员代操作。
39. 客户被两个销售员同时跟进 → 归属唯一，另一人只能查看公共信息。
40. 新客户注册时，若目标销售员名额已满 → 仍按"名下客户数最少"分配，分配后主管可改派。

### 10.7 账期与财务

41. 一笔回款核销多单时，客户未指定核销顺序 → 默认按订单时间先后核销。
42. 登记的回款金额大于所选订单未回款合计 → 拦截并提示"回款金额超出待核销金额"，不允许形成预收款。
43. 逾期客户仍想下单 → 只能预付，页面需明确提示原因与解除方式。
44. 财务登记回款后发现有误 → 冲销并重新登记，两步都留痕，额度同步回退。
45. 发票开错需重开 → 标记原发票作废，重新上传新 PDF，保留历史记录。

### 10.8 在线客服

46. 客户绑定的客服已离线 → 会话转排队，由在线客服接续；客户侧提示"客服离线，正在为您转接"。
47. 客服接待达上限（默认 10 个会话）→ 不再分配新会话，客户进入排队。
48. **全员离线或非工作时间** → 客户看到留言框与预计回复时间，留言转为待接入会话，客服上线后收到提醒。
49. 客户在会话中发来图稿 → 消息附件与定制单图稿需区分存储，避免混用；客服可一键"转存为定制图稿"。
50. 客户网络中断后重连 → 自动补拉断线期间消息，不重复、不跳序，并有"已重新连接"提示。
51. 客服误发消息 → **不支持撤回**，需通过后续消息更正；系统保留完整记录。
52. 客户 30 分钟无新消息 → 会话自动结束，客户再咨询可新建会话；历史会话可查。
53. 客户同时打开多个咨询入口（商品页 + 订单页）→ **并入同一进行中会话**，不重复建会话。
54. 客服转接后原客服退出 → 客户侧显示转接提示，新客服可见完整历史消息，无需客户重复描述。
55. 客服关闭浏览器或断网 → 该客服的进行中会话保留，恢复后继续；超过 10 分钟未恢复则释放其接待名额。

### 10.9 权限与数据

56. 仓管点击订单详情 → 不显示客户手机号与成交价，只显示收货地址与商品数量。
57. 销售员导出客户列表 → 只能导出自己名下，且手机号脱敏。
58. 客服查看订单 → 可见金额与状态，不可见支付流水号。
59. 超管停用某管理员 → 其名下会话与待办需转交，不能凭空消失。

## 11. 业务约束与非功能要求（业务语言表述）

| 类别 | 要求 |
| --- | --- |
| 金额精度 | 所有金额以"分"为最小单位计算，禁止出现浮点误差；展示保留两位小数 |
| 状态一致性 | 任何界面展示的订单状态，必须来自同一次查询结果，不允许前端拼接推断 |
| 幂等 | 支付回调、退款回调、回款登记、库存扣减，重复提交不得产生重复业务结果 |
| 留痕 | 价格变更、库存变动、订单状态变更、审批动作、权限变更，全部留痕且不可篡改 |
| 数据保留 | 订单与支付记录永久保留；客服从话记录 36 个月；图稿 24 个月；操作日志 36 个月 |
| 权限 | 数据权限在查询层生效，导出、搜索、统计同样受限 |
| 安全 | 密码加密存储；登录失败 5 次锁定 15 分钟；高风险操作需二次确认 |
| 可用性 | 核心下单与支付链路故障时给出明确提示而非白屏，提供"稍后重试" |
| 实时性 | 客服消息正常网络下 1 秒内送达；断线重连后不丢消息、不重复、保持顺序；离线状态必须对客户可见 |
| 时效 | 支付超时 30 分钟、自动确认收货 15 天、审图 24 小时、退款审核 48 小时、会话首响 5 分钟、会话超时 30 分钟，均可配置 |

| 兼容 | 用户端适配主流 PC 浏览器（Chrome/Edge/Safari 最新两个大版本）与 1366 及以上分辨率 |

> 本节刻意不涉及技术选型与实现方案，仅约束"业务上必须成立的结果"。

## 12. 范围边界

### 12.1 一期包含

- **用户端**：注册登录、商品浏览搜索、商品详情、定制下单、购物车、下单支付（模拟）、订单与包裹跟踪、退款申请、会员中心、企业专区、站内信与在线客服、地址与发票
- **管理端**：工作台、商品与 SKU、定价（三层价 + 阶梯 + 一客一价）、库存与手工入库/报损/盘点、订单与拆单发货、定制审核、退款、客户与归属、会员等级、在线客服工作台、财务（应收台账 / 回款核销 / 退款审核 / 发票 / 合同）、三张报表、账号权限、操作日志
- **支付**：模拟支付 + 标准回调机制（可替换为真实渠道）

### 12.2 一期不做（明确排除，避免范围蔓延）

| 不做的事 | 替代方案 / 原因 |
| --- | --- |
| 采购单流转与供应商管理 | 库存不足由仓管"手工入库"，本系统是销售系统不是 ERP |
| 采购成本移动加权平均 | 成本价手工录入或取最近一次入库价 |
| 客服语音/视频通话、群聊 | 仅做文字、图片、商品卡、订单卡 |
| 消息撤回 | 增加消息模型复杂度，误发通过后续消息更正 |
| 机器人自动应答（智能客服） | 一期全部人工接待 |
| 客服满意度评价 | 一期只做首响与接待量指标 |
| 商品评价与晒单 | 未提出需求 |
| 预收款账户、退款冲抵应收 | 回款只做登记与核销，不做资金池 |
| 合并开票 | 一张订单一张发票 |
| 积分商城、积分兑换商品 | 积分仅抵现 |
| 商品组合套装 | 组合商品库存扣减易出错 |
| 企业子账号 | 一个企业一个账号 |
| 销售员提成自动计算 | 只出业绩数据，提成线下核算 |
| 等级自动降级 | 只保留人工降级 |
| 多仓库/多门店、调拨 | 单仓多库位 |
| 优惠券、满减、拼团、秒杀 | 与取价规则冲突，先不做 |
| 物流轨迹查询、电子面单 | 仅录入单号 |
| 移动端 App / 小程序 | 两端均为 PC Web |
| 电子签、税控系统对接 | 合同与发票只做附件归档 |
| 毛利、周转、滞销、客服绩效报表 | 报表收敛为三张 |

## 14. 决策记录（20 项已定稿）

| 编号 | 决策结论 | 说明 |
| --- | --- | --- |
| Q1 | 会员只保留**三级**（普通 / VIP1 / VIP2），门槛与折扣后台可配 | 档位越多前端展示与计算越复杂，三级足以覆盖分层运营 |
| Q2 | **不启用自动降级**，只保留人工降级 | 滚动周期结算的边界情况多、易出错；人工降级已能满足管理诉求 |
| Q3 | 审图由**客服兼任**，不新增设计角色 | 审图与客服职责同源，避免角色与权限体系膨胀 |
| Q4 | 积分**仅抵现**，100 分 = 1 元，单笔上限 30%，不做积分商城 | 积分商城前后端工作量极高，B2B 场景收益低 |
| Q5 | UV 计费 = **面数 + 数量阶梯**，**去掉颜色系数** | 颜色系数易导致前端试算与后端结算不一致 |
| Q6 | 部分退货不满包邮门槛，**不补扣运费** | 降低退款计算复杂度，避免客户争议 |
| Q7 | **做**缺货到货提醒（站内信） | 实现成本低，能形成"缺货—补货—转化"的闭环 |
| Q8 | 首页推荐**按销量倒序 + 上架时间倒序**，不做人工排序后台 | 省掉一套运营配置界面 |
| Q9 | **不支持**到店自提，全走快递 | 自提会引入库存扣减与物流状态的分支 |
| Q10 | 成本价**手工录入或取最近入库价**，不做移动加权平均 | 加权平均的精度问题会在对账时暴露 |
| Q11 | **不做**客服满意度评价 | 一期只需首响与接待量指标 |
| Q12 | 销售只出**业绩数据**，不自动算提成 | 提成涉及财务合规，规则一旦写死难以调整 |
| Q13 | 长期不传图稿**转人工客服跟单** | 自动取消 + 自动退款 + 库存回补的链路风险过高 |
| Q14 | 标品与定制件**必须支持拆单发货**，按订单行与数量拆分 | 符合实际：标品可先发，定制件排产完再发 |
| Q15 | 企业子账号**一期坚决不做** | 多账号会让权限体系翻倍 |
| Q16 | 客服消息**不支持撤回** | 撤回会显著增加消息模型的复杂度 |
| Q17 | **单仓多库位** | 保持库存模型简单，只有一层仓与库位 |
| Q18 | 商品组合套装**一期不做** | 组合商品的库存扣减极易出错 |
| Q19 | 新客户分配**按名下客户数最少轮询**，主管可改派 | 规则简单可解释，避免客户集中到个别销售 |
| Q20 | 电子面单**仅录入单号**，不对接快递接口 | 对接成本高、维护烦，业务价值有限 |
| Q21 | 取价**不取低，只认严格优先级**；协议价生效后不叠阶梯；阶梯优先于会员 | "取低"会导致协议 5 折再叠阶梯 4.5 折的亏本单；严格优先级规则唯一、可解释、可审计 |
